## 1. PROJECT GOAL

Build a reproducible, single-command pipeline that takes a raw podcast MP4 and produces a polished, Premiere Pro sequence ready for final review. No manual editing to start the sequence — it should open in Premiere already edited.

**The pipeline does:**
1. Transcribes the audio with word-level timestamps (mlx_whisper)
2. Analyzes the transcript to decide what to cut (silences, pre/post-show chit-chat, connection/lag complaints) and what to keep (main interview content)
3. Identifies the episode intro (often recorded at the END of the raw file) and moves it to the front
4. Selects 2–3 "teaser" clips (compelling quotes) to open the episode before the intro
5. Snaps all cut boundaries to the nearest word edge so cuts fall in silence, not mid-sentence
6. Builds the edited sequence in Premiere Pro via a CEP bridge (file-based IPC at `/tmp/premiere-mcp-bridge/`)
7. Runs a QA check (via that same bridge) and refuses to declare success until the sequence passes

**"Done" means:** A Premiere sequence named after the episode opens with a teaser, flows into the intro, plays the edited interview, and ends on the outro. All cuts are in silence. A1 audio fader is at 0 dB. No −∞ audio artifacts. Content QA confirms nothing important was cut. The editor can add music, color correction, and export — nothing structural remains.

**Current episode being worked:** `anndy-lian-web4-podcast.mp4` — 58.7 min raw, ~51 min edited, guest Anndy Lian discussing Web4/AI/crypto.

### A. Audio −∞ bug in Premiere (ACTIVE — may affect current sequence)

**What:** The "Anndy Lian Web4 Edit" sequence currently in Premiere may have Volume Level keyframes from a previous build attempt that set value=0.0 (silence) on the A1 clips. This makes the Audio Clip Mixer show −∞ dB and kills audio playback.

## 4. THE PLAN / NEXT STEPS

### Step 1 — Write `content_qa.py` (highest priority)

**File to create:** `podcast-pipeline/content_qa.py`

**What it does:**
1. Loads transcript + `content_edit.json`
2. For each cut, extracts the transcript text that was removed and classifies it:
   - `silence` — no words in that range
   - `lag` — contains "lagging", "lost you", "internet", "freeze", etc.
   - `pre-show` / `post-show` — structural cuts at start/end
   - `⚠ REAL CONTENT` — actual podcast content accidentally cut
3. Builds the "edited transcript" (text of kept segments joined together)
4. Calls Claude API to: (a) summarize the edited transcript, (b) compare to original for coherence, (c) flag any abrupt gaps
5. Prints structured report; exits 1 if real content was cut

EDITED TRANSCRIPT OVERVIEW:
  [Claude's ~3-paragraph summary of what the 51-min edit covers]

  [Claude assessment: does the flow make sense? Any abrupt topic jumps?]

## 6. WATCH OUT FOR (GOTCHAS & CONSTRAINTS)

### Audio keyframes = guaranteed silence
Any call to `lp.setTimeVarying(true)` + `lp.addKey()` + `lp.setValueAtKey(ticks, 0)` on an A1 clip's Volume Level will silence that clip. `0` in the Volume Level scale is LINEAR amplitude = silence (−∞ dB). Unity gain is `0.17782793939114` (Premiere's internal default). DO NOT add any Volume Level keyframes to A1 clips. See memory file `feedback_premiere_audio_transitions.md`.

### AudioTrack.components causes CEP crash
Accessing `seq.audioTracks[0].components` in ExtendScript crashes CEP with "ExtendScript execution failed via CEP evalScript()." The track fader cannot be read or set programmatically. If the A1 fader gets stuck at −∞, the user must manually drag it to 0 in the Audio Track Mixer. A rebuild (which deletes and recreates the sequence) also resets it.

### QE transition lists are always empty
`qe.project.getVideoTransitionList()` and `qe.project.getAudioTransitionList()` both return 0 items when called via CEP bridge. Video AND audio transitions cannot be added programmatically. The MCP's `add_transition`, `batch_add_transitions`, `add_audio_transition`, and `batch_add_audio_transitions` tools all fail for this reason. Manual Cmd+Shift+D is the only workaround.

### `createNewSequenceFromClips` must be called before `overwriteClip`
The first clip in the sequence must be created via `proj.createNewSequenceFromClips(name, [srcItem])`. The sequence derives its frame rate and resolution from that first source clip. Subsequent clips are added via `seq.videoTracks[0].overwriteClip(srcItem, posT)`. The cursor must be tracked manually in Python (not read from Premiere) to avoid drift.

### Source MP4 must be imported before building
`build_content_sequence.py` looks for the source filename in `proj.rootItem`. If it's not there, it returns `{error: "Source not found in Premiere project bin: <name>"}`. Import via File > Import in Premiere first.

### Whisper word timestamps are nested, not flat
The transcript JSON format is `{"segments": [{"words": [{"word": "...", "start": 0.0, "end": 0.5}]}]}`. The word-level data is nested under segments, not at the top level. The `load_and_flatten_transcript()` function in `podcast_content_edit.py` handles this correctly. `claudedit_helpers.load_transcript()` does NOT — it expects a flat format and returns an empty list for this format.

### Intro is at the END of the raw file
For the Anndy Lian episode, the show intro ("Hi guys. I'm Anndy Lian…") was recorded AFTER the main conversation. It lives at ~52:44 in the raw file (3155.28s), followed by post-recording banter. This is common — hosts record the intro after knowing what they discussed. The pipeline detects this by searching the last 20% of the file for self-introduction patterns. Do not assume intros are at the start of the file.

### The Anndy Lian content_edit.json is hand-tuned
The file at `/tmp/podcast-edit/content_edit.json` was built through many iterations. Teaser clips, intro boundaries, lag cut timestamps, and word-boundary snapping were applied manually. Running `podcast_pipeline.py` WITHOUT `--skip-analyze` will overwrite this with the simpler automated version (no teasers, rougher boundaries).

### ANTHROPIC_API_KEY not available in subprocess
The pipeline runs `build_content_sequence.py` as a subprocess. Environment variables like `ANTHROPIC_API_KEY` are available in the main shell session but not passed to subprocesses by `subprocess.run()`. Any Claude API calls must happen in the main process (in `podcast_pipeline.py` directly), not via subprocess.

### Ticks, frames, and floating point
- 1 second = 254,016,000,000 ticks
- 1 frame at 30fps = 8,467,200,000 ticks
- ALL timecodes passed to Premiere must be frame-snapped: `Math.round(seconds * 30) * 8467200000`
- The `cursor` variable tracking the current timeline position must be accumulated using frame-snapped arithmetic to avoid drift over many clips

### Premiere MCP bridge

The bridge works via filesystem polling:

- CEP writes `response-<id>.json` back
- Python reads and deletes the response file

The bridge is SINGLE-THREADED. Never send concurrent bridge calls.

## 8. KEY DECISIONS LOG

- **Single-cam workflow, not multi-cam.** The existing `podcast_ingest.py`/`podcast_edit.py`/`build_podcast_sequence.py` scripts are for multi-cam setups (host cam + guest cam + reference). The Anndy Lian podcast is single-camera (one MP4, both speakers). The new `build_content_sequence.py` handles single-cam only.

- **Word-boundary snapping, not silence detection.** ffmpeg's `silencedetect` returned 0 results on this podcast audio (too dynamic for -30dB threshold). Instead, gaps ≥ 2s between consecutive Whisper word timestamps are used as the silence detection method. All cut start/end timestamps are then snapped to the nearest actual word boundary within 0.6s.

- **2-second minimum silence threshold.** Industry standard for podcasts. Sub-2s pauses are natural speech rhythm (breathing, thinking). Removing them makes the edit sound robotic. Only true dead air (>2s gap between words) is cut.

- **No audio keyframe fades.** Three approaches were tried and all failed or caused damage: (1) `setValueAtKey(t, -60)` corrupts audio because -60 is below minimum on the linear scale; (2) `setValueAtKey(t, 0)` silences the clip because 0 = −∞ dB on the linear scale; (3) QE audio transitions not available via CEP. Word-boundary snapping makes hard cuts inaudible anyway.

- **Volume Level linear amplitude scale = 0.0 is silence, 0.17782 is 0 dB.** NOT dB values. The Premiere `Volume Level` `ComponentParam` uses linear amplitude internally. If you ever need to add fades, the correct values are: silence = `0.0`, unity = `0.17782793939114`. API: `lp.addKey(Time_object)` then `lp.setValueAtKey(String_ticks, linear_value)`. Do NOT use `addKeyframe(string)` — that method doesn't exist.

- **Intro is in the last 20% of the file.** Search heuristic confirmed empirically. The Anndy Lian intro ("Hi guys. I'm Anndy Lian…") was at 89.6% through the raw file (3155s of 3523s). Detection: regex for "hi guys", "I'm [name]", etc. in the last 20% of segments. End boundary: look forward up to 90s for "thank you", "take a look", "bye".

- **Teaser clips from main content only (88.3s–3140s).** No teasers from the pre-show or post-recording sections. The three selected clips are deliberately spread across the episode: 16.5m (market size), 22.7m (greed problem), 26.3m (AI solution) — they form a logical arc.

- **False-start/"Yeah Yeah" removal was disabled.** An initial attempt to cut repeated consecutive words ("Yes. Yes.", "Right. Right.") removed too much natural back-channeling. The algorithm incorrectly flagged conversational acknowledgments as errors. This was reverted. If repeat detection is re-added, it must distinguish between: (a) literal false starts mid-sentence (cut the first) vs (b) two speakers saying the same filler word in quick succession (keep both).

- **The Premiere QA gate blocks the pipeline on failure.** `build_content_sequence.py` runs a QA bridge call after building. If V1/A1 counts don't match, A1 is muted, or short clips exist, it prints `✗ QA FAILED` and exits 1. This prevents declaring success on a broken sequence. The NEXT thing needed is content-level QA (dialog verification) in `content_qa.py`.
